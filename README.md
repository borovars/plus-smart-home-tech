## Smart Home Tech

Современная учебная система для управления умным домом и интернет‑магазина товаров для него. Проект моделирует полный путь заказа: от витрины и корзины до склада, оплаты, доставки и телеметрии устройств.

### Краткое описание

**Smart Home Tech** — это набор микросервисов, реализующих:
- **интернет‑магазин** товаров для умного дома (каталог, корзина, оформление и оплата заказов, доставка);
- **подсистему умного дома** с сбором телеметрии от устройств, обработкой сценариев и аналитикой.

Проект построен как учебный пример промышленной микросервисной архитектуры на базе экосистемы Spring.

### Стек технологий

- **Язык и платформа**
  - **Java 21**
  - **Spring Boot 3.x** (`spring-boot-starter-parent`)
  - **Spring Cloud** (Eureka, Gateway, Config Server, OpenFeign, Resilience4j)
- **Транспорт и интеграция**
  - **HTTP / REST** (через API‑шлюз)
  - **Apache Kafka** для телеметрии и асинхронных событий
  - **gRPC** для части взаимодействий в подсистеме телеметрии
- **Хранение данных**
  - **PostgreSQL 16** — отдельные БД для каждого доменного сервиса (store, cart, order, payment, delivery, warehouse, analyzer)
  - Инициализация схем через SQL‑скрипты (`docker/postgres/*.sql`)
- **Сериализация и сообщения**
  - **Avro** и **Protobuf** для сообщений телеметрии
- **Инфраструктура и оркестрация**
  - **Docker** и **Docker Compose** (`compose.yaml`)
  - **Spring Cloud Config Server** (централизованная конфигурация)
  - **Eureka Discovery Server** (сервис‑регистрация)
  - **Spring Cloud Gateway** (API‑шлюз)

### Архитектура

Проект разделён на несколько логических модулей:

- **`infra`** — инфраструктурные сервисы:
  - `config-server` — централизованный сервер конфигурации Spring Cloud Config.
  - `discovery-server` — сервер сервис‑регистрации (Eureka).
  - `gateway` — входная точка HTTP‑трафика (Spring Cloud Gateway), маршрутизирующая запросы к бизнес‑сервисам.
- **`commerce`** — доменные сервисы интернет‑магазина:
  - `shopping-store` — каталог товаров для умного дома.
  - `shopping-cart` — корзина пользователя.
  - `order` — управление заказами и их статусами.
  - `payment` — сервис платежей и статусов оплаты.
  - `delivery` — сервис доставки заказов.
  - `warehouse` — склад и резервирование остатков.
  - `interaction-api` — общие OpenFeign‑клиенты, DTO и исключения для взаимодействия между сервисами.
- **`telemetry`** — подсистема телеметрии умного дома:
  - `collector` — приём телеметрии от сенсоров/хабов (REST + gRPC), публикация событий в Kafka.
  - `aggregator` — агрегация потоков телеметрии и пересборка сообщений.
  - `analyzer` — анализ сценариев умного дома и работа с правилами/условиями.
  - `serialization` (`avro-schemas`, `proto-schemas`) — схемы сообщений и вспомогательный код сериализации.

Связь сервисов организована через:
- **API‑шлюз** (`infra/gateway`) — единая входная точка для внешних клиентов;
- **Spring Cloud OpenFeign** (`commerce/interaction-api`) — типобезопасные HTTP‑клиенты между микросервисами;
- **Kafka** и **gRPC** — коммуникации внутри подсистемы телеметрии.

### Краткое описание основных эндпоинтов

Ниже перечислены ключевые группы эндпоинтов (точные URL и HTTP‑методы можно посмотреть в контроллерах и Feign‑интерфейсах модуля `interaction-api`).

- **Каталог товаров (`shopping-store`)**
  - Получение списка товаров по категории (с пагинацией).
  - Получение товара по идентификатору.
  - Создание/обновление/удаление товара.
  - Обновление доступного количества товара на складе/витрине.

- **Корзина (`shopping-cart`)**
  - Получение корзины пользователя.
  - Добавление товаров в корзину и изменение количества.
  - Удаление товаров из корзины.
  - Очистка корзины пользователя.

- **Заказы (`order`)**
  - Получение списка заказов пользователя.
  - Создание нового заказа на основе корзины и выбранных товаров.
  - Обработка бизнес‑событий: оплата, неуспешная оплата, доставка, неуспешная доставка, сборка, неуспешная сборка, завершение заказа.
  - Расчёт общей стоимости заказа и стоимости доставки.

- **Платежи (`payment`)**
  - Инициация оплаты заказа.
  - Обновление статуса платежа (успешно/ошибка).

- **Склад (`warehouse`)**
  - Резервирование товаров при создании заказа.
  - Обновление остатков при возврате/отмене.

- **Доставка (`delivery`)**
  - Инициирование доставки заказа.
  - Обновление статуса доставки (в процессе, успешно, ошибка).

- **Телеметрия (`telemetry/collector`, `analyzer`, `aggregator`)**
  - Приём событий от сенсоров (температура, движение, освещённость и т.п.).
  - Приём событий от хабов и сценариев (добавление/удаление устройств и сценариев).
  - Запись событий в Kafka‑топики `telemetry.*`.
  - Обработка сценариев и условий, запись результатов в БД анализатора.

### Установка и запуск

#### Предварительные требования

- Установлены:
  - **Git**
  - **Docker** и **Docker Compose**
  - **Java 21+** и **Maven 3.9+** (если планируется локальная сборка артефактов)
- Свободные порты для:
  - сервисов PostgreSQL (диапазон `6535–6541`);
  - Kafka (`9092`, `9101`);
  - микросервисов (`808x`, `90xx` и т.д., см. `application.yaml` соответствующих модулей).

> **Важно:** все таблицы и базовые данные для доменных БД создаются автоматически при старте контейнеров PostgreSQL с помощью SQL‑скриптов из каталога `docker/postgres`. Никакой ручной инициализации схемы не требуется.

#### Клонирование репозитория

```bash
git clone https://github.com/<your-org>/plus-smart-home-tech4.git
cd plus-smart-home-tech4
```

*(при необходимости замените URL на актуальный для вашего форка/репозитория)*

#### Установка зависимостей (опционально, для локальной сборки)

Если вы планируете собирать микросервисы локально перед запуском:

```bash
mvn clean install
```

Команда выполнит сборку всех модулей (`telemetry`, `infra`, `commerce` и т.д.) согласно корневому `pom.xml`.

#### Настройка переменных окружения

По умолчанию конфигурация сервисов берётся:
- из **Config Server** (`infra/config-server`, каталог `src/main/resources/config`);
- из настроек Docker Compose (`compose.yaml`).

#### Запуск приложения

Для поднятия всей инфраструктуры и сервисов используйте **Docker Compose**:

```bash
docker compose up -d
```

Команда запустит:
- Kafka и вспомогательные сервисы;
- все контейнеры PostgreSQL (для `store`, `cart`, `order`, `payment`, `delivery`, `warehouse`, `analyzer` и т.д.);
- инфраструктурные сервисы (`config-server`, `discovery-server`, `gateway`);
- доменные сервисы (`shopping-store`, `shopping-cart`, `order`, `payment`, `delivery`, `warehouse`);
- сервисы телеметрии (`collector`, `aggregator`, `analyzer` и др., если они описаны в `compose.yaml`).

При первом старте:
- **таблицы во всех БД будут автоматически созданы** за счёт монтирования SQL‑скриптов из `docker/postgres/*.sql` в `/docker-entrypoint-initdb.d` контейнеров PostgreSQL;
- будут применены начальные схемы и данные, описанные в соответствующих `.sql` файлах.

Чтобы остановить все контейнеры:

```bash
docker compose down
```

### Использование

Типичный сценарий работы с системой:

1. **Каталог и корзина**
   - Клиент через API‑шлюз запрашивает список товаров по категориям (данные приходят из сервиса `shopping-store`).
   - Добавляет выбранные товары в корзину; изменения в корзине обрабатывает сервис `shopping-cart`.
2. **Оформление заказа**
   - Клиент инициирует создание заказа на основе содержимого корзины.
   - Сервис `order` резервирует товары на складе (`warehouse`) и формирует заказ.
3. **Оплата и доставка**
   - Сервис `payment` инициирует и подтверждает оплату.
   - При успешной оплате сервис `order` обновляет статус заказа и инициирует доставку через сервис `delivery`.
4. **Телеметрия умного дома**
   - Физические или симулированные устройства отправляют телеметрию в сервис `collector` (HTTP/gRPC).
   - События попадают в Kafka, затем обрабатываются `aggregator` и `analyzer` для расчёта сценариев умного дома (включить свет, отрегулировать климат и т.д.).

Примеры базовых HTTP‑запросов (через API‑шлюз, URL могут отличаться в зависимости от настроек роутинга):

```http
GET /api/store/products?category=CLIMATE&page=0&size=20     # получение списка товаров
GET /api/cart                                              # получение корзины текущего пользователя
POST /api/cart                                             # добавление товаров в корзину
POST /api/orders                                           # создание нового заказа
POST /api/orders/{id}/pay                                  # инициировать оплату
POST /api/orders/{id}/deliver                              # инициировать доставку
```

Точные маршруты смотрите в:
- контроллерах модулей `shopping-store`, `shopping-cart`, `order`, `payment`, `delivery`, `warehouse`;
- интерфейсах Feign‑клиентов в модуле `commerce/interaction-api`;
- правилах маршрутизации API‑шлюза (`infra/gateway`).

### Структура проекта

Основные директории репозитория:

- **`commerce/`**
  - `shopping-store/` — сервис каталога товаров.
  - `shopping-cart/` — сервис корзины.
  - `order/` — сервис управления заказами.
  - `payment/` — сервис платежей.
  - `delivery/` — сервис доставки.
  - `warehouse/` — сервис склада.
  - `interaction-api/` — общие Feign‑клиенты, DTO, модели и исключения для взаимодействия между сервисами.
- **`infra/`**
  - `config-server/` — Config Server c YAML‑конфигурацией в `src/main/resources/config`.
  - `discovery-server/` — Eureka‑сервер для регистрации всех микросервисов.
  - `gateway/` — API‑шлюз и единая точка входа для клиентов.
- **`telemetry/`**
  - `collector/` — приём и первичная обработка телеметрии, публикация в Kafka.
  - `aggregator/` — агрегация событий телеметрии.
  - `analyzer/` — анализ сценариев и условий, работа с БД `analyzer`.
  - `serialization/` (`avro-schemas`, `proto-schemas`) — схемы и утилиты сериализации сообщений.
- **`docker/`**
  - `postgres/*.sql` — SQL‑скрипты инициализации баз данных (таблицы и стартовые данные создаются автоматически при старте контейнеров БД).
- **`compose.yaml`**
  - Описание всех контейнеров (Kafka, БД, микросервисы и вспомогательные сервисы).
- **`pom.xml` (в корне и модулях)**
  - Maven‑конфигурация, управление зависимостями и модулями проекта.
